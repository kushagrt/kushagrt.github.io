Live operations dashboard (Google Apps Script web app)

Flipkart Minutes · self-initiated · adopted by the central team for pan-India use

The problem

Teams tracked store performance in shared Google Sheets. When one person applied a filter, everyone else's view changed. How data is displayed shapes how people interpret it, so this caused confusion and slowed decisions.

What I built

A web app where each user loads the metrics they care about for any set of stores, with hourly trends, independent of what anyone else is viewing. Built on Apps Script with no engineering resources, and nobody asked for it.

Outcome

Used by store managers, cluster heads, city leaders and the regional head, roughly 5–7K users. The central team adopted it for pan-India operations, and I received formal recognition by email.

Companion tool

A telecalling app for field recruiters and fleet operations managers (~300 users), built with the same approach.

Scaling a dark-store network from 23 to 51

Flipkart Minutes, Pune · Sep 2025 – present

Scope

End-to-end ownership of expansion, go-live, in-store and last-mile operations, cost and growth, coordinating with growth, analytics, security, line haul, sourcing hubs, the Founder's Office and PMO.

What I learned

Expansion alone didn't lower cost per order, because coverage was still incomplete. The lever is shrinking each store's serviceable polygon so orders per store rise.

Experimentation

I ran continuous A/B tests on rider rate cards and operating constructs, scaling only what worked, and introduced conditional and part-timer rate cards as cost levers.
